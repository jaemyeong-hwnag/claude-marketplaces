# 작성 규칙 (단일 원본)

플러그인 파일의 **내용 형식**을 정한다. 스킬 · 커맨드 · 에이전트의 프런트매터, 스킬 본문과 참조 문서의 크기, README 의 절 구성.
기계 검증은 [`scripts/validate-authoring.sh`](../scripts/validate-authoring.sh).

이름은 `plugin-naming`, 파일 위치는 `marketplace-directory-structure`, 버전은 `plugin-versioning` 이 본다. 여기서는 **이미 올바른 자리에 있는 파일의 안쪽**만 본다.

## 1. 스킬 · 커맨드 · 에이전트

| 조항 | 내용 | 판정 |
|---|---|---|
| `A-01` | 프런트매터가 `---` 로 시작하고 `---` 로 닫힌다 | 차단 |
| `A-02` | 스킬 `name` 은 디렉터리명, 에이전트 `name` 은 파일명과 같다 | 차단 |
| `A-03` | `description` 이 있다 (스킬 · 커맨드 · 에이전트 모두) | 차단 |
| `A-04` | 스킬 description 에 "언제 쓰는가" 가 있다 — `~ 때 사용한다` 또는 `~ 때 참조한다` (추가할 때 · 고칠 때 · 쓸 때 …) | 차단 |
| `A-05` | 스킬 description 이 300자를 넘으면 경고 | 경고 |

`name` 이 디렉터리명과 다르면 `plugin-naming` 이 검사한 이름과 실제 호출 이름이 갈린다. Claude Code 는 `name` 이 있으면 그것을 쓴다.

### description — 상시 비용이다

스킬·커맨드·에이전트 description 은 **매 세션 컨텍스트에 들어간다.** `claude plugin details` 로 보면 스킬 하나가 ~250 토큰이다 (한국어 250 ~ 300자).

담을 것 셋 — 순서는 강제하지 않는다.

1. 무엇을 하는가 (한 문장)
2. 언제 쓰는가 — `~할 때 사용한다` (`A-04`)
3. 트리거 키워드 — 관찰 가능한 단어·명령·파일명. "~일 때" 같은 추상 조건은 다른 스킬과 겹친다

줄일 때는 트리거의 **동의어 중복**부터 뺀다. "언제 쓰는가" 는 줄이지 않는다.

## 2. 스킬 본문과 참조 문서

| 조항 | 내용 | 판정 |
|---|---|---|
| `A-06` | SKILL.md 가 200줄을 넘으면 `references/` 로 나누라고 경고 | 경고 |
| `A-07` | `references/` 파일이 500줄을 넘으면 경고 | 경고 |
| `A-08` | SKILL.md 의 상대 경로 링크가 가리키는 파일이 있다 | 차단 |
| `A-09` | `skills/` · `references/` 안에 외부 URL(`http://` · `https://`)을 쓰지 않는다 — 내용을 직접 넣는다 | 차단 |

- 참조 데이터(템플릿 · 예시 · 체크리스트 · 규칙 원본)는 **플러그인 루트 `references/`** 에 둔다. 여러 스킬과 스크립트가 같이 읽는다
- `A-09` 의 이유는 오프라인 동작이다. 출처를 밝혀야 하면 URL 대신 "저장소 · 경로" 를 글로 적는다
- `plugin.json` 의 `homepage` 처럼 메타데이터 필드의 URL 과 README 의 URL 은 대상이 아니다
- 형식(`.md` · `.json`)과 바이너리 금지는 구조 규칙 `P-07` 이 이미 본다

## 3. README

```markdown
# {plugin-name}

{한 줄 설명}

## 설치

## 의존성

## 포함된 스킬

## 포함된 에이전트

## 포함된 훅

## 주의

## (플러그인별 절 — 자유)

## 변경 이력
```

| 조항 | 내용 | 판정 |
|---|---|---|
| `A-20` | 첫 제목이 `# {plugin.json 의 name}` 이다 | 차단 |
| `A-21` | `## 설치` · `## 의존성` · `## 변경 이력` 이 있다 | 차단 |
| `A-22` | 스킬·커맨드가 있으면 `## 포함된 스킬`, 에이전트가 있으면 `## 포함된 에이전트`, `hooks/hooks.json` 이 있으면 `## 포함된 훅` 이 있다 | 차단 |
| `A-23` | 템플릿 절은 위 순서를 지키고 `## 변경 이력` 이 마지막 절이다 | 차단 |
| `A-24` | `## 포함된 스킬` 표의 첫 칸 = `skills/*/` 이름 + `/{커맨드 이름}`. 빠진 것도 없는 것도 없다 | 차단 |
| `A-25` | `## 포함된 에이전트` 표의 첫 칸 = `agents/*.md` 이름 | 차단 |
| `A-26` | `## 포함된 훅` 에 `hooks.json` 의 이벤트가 모두 나온다 | 차단 |
| `A-27` | `## 의존성` 에 `dependencies` 의 이름이 모두 나온다. 없으면 "없음" | 차단 |
| `A-28` | public 플러그인의 `## 설치` 에 `{name}@` 설치 명령이 있다 | 차단 |

표와 실제 구성요소를 대조하는 `A-24` ~ `A-27` 이 핵심이다. 스킬을 추가하고 README 를 잊으면 잡힌다 — `V-06` 이 CHANGELOG 누락을 잡는 것과 같은 구조다.

- 커맨드는 `claude plugin details` 가 스킬 목록에 올리므로 스킬 표에 `/{이름}` 으로 넣는다
- 템플릿에 없는 절(`## 테스트`, `## 규칙 요약` …)은 자유다. 필수 절 사이 어디든 둘 수 있지만 `## 변경 이력` 뒤에는 둘 수 없다
- internal 플러그인의 설치 절은 "SessionStart 훅이 설치한다" 로 충분하다

## 4. 기계가 판정할 것 / AI 가 판단할 것

| | 담당 | 무엇을 |
|---|---|---|
| 정량 | `validate-authoring.sh` | `A-01` ~ `A-09`, `A-20` ~ `A-28` |
| 판단 | AI (`document-create` 스킬) | description 의 "무엇을 하는가" 가 정확한가, 트리거가 다른 스킬과 겹치지 않는가, 템플릿·예시를 `references/` 로 뺄 때인가, README 한 줄 설명이 description 과 같은 뜻인가 |

## 5. 훅

| 이벤트 | 대상 | 동작 |
|---|---|---|
| `PreToolUse(Write)` | `skills/*/SKILL.md` · `commands/*.md` · `agents/*.md` | 새 내용에서 `A-01` ~ `A-04` 를 보고 **차단** |
| `PostToolUse(Write\|Edit)` | 플러그인 안의 README · 스킬 · 커맨드 · 에이전트 · `hooks.json` · `plugin.json` · `references/` | 그 플러그인 전체를 검사해 **알린다** |

README 대조(`A-24` ~ `A-27`)는 막지 않는다. 스킬을 만들고 README 를 고치는 데 두 번의 편집이 필요하다 — `plugin-versioning` 의 `V-06` 과 같은 이유다. `--all` 에서는 막는다.

`Edit` 는 부분 문자열만 오므로 `PreToolUse` 에서 보지 않는다. 저장 뒤 `PostToolUse` 가 본다.

## 6. 검증

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/validate-authoring.sh" internal-plugins/plugin-authoring   # 플러그인 하나
"${CLAUDE_PLUGIN_ROOT}/scripts/validate-authoring.sh" --all .                             # 저장소 전체
```

종료 코드 `2` 가 위반이다. 경고만 있으면 `0` 이다.
