# 버전 관리 테스트

`scripts/validate-versioning.sh` 의 회귀 테스트. 버전 규칙이나 스크립트를 고치면 여기부터 돌린다.

이름 규칙 테스트는 `internal-plugins/plugin-naming/test/`, 디렉터리 구조 테스트는
`internal-plugins/marketplace-directory-structure/test/`, 배치·배포 정책 테스트는 저장소 `test/` 에 있다. 섞지 않는다.

## 실행

```bash
test/validate-versioning.test.sh          # 전체
test/validate-versioning.test.sh TC-V3    # ID 접두사로 필터
```

종료 코드 0 이면 전체 통과다. 세션 없이 돌아가므로 커밋 전 검증에 그대로 쓴다.

## TC 추가 규칙

- 규칙(`references/versioning-rules.md`)에 조항을 추가하면 TC 도 같이 추가한다. 조항 번호를 TC 설명에 남긴다.
- ID 구간을 지킨다. A 값 `TC-V0x`~`TC-V1x` / B CHANGELOG `TC-V2x`~`TC-V3x` / C 엔트리 `TC-V4x`~`TC-V5x` / D 태그 `TC-V6x` / E Pre 훅 `TC-V7x` / F Post 훅 `TC-V8x` / G CLI `TC-V9x`.
- 막는 TC 만 늘리지 않는다. "허용해야 하는 케이스"를 쌍으로 넣어야 과잉 차단을 잡는다.

## 알려진 한계 (실패로 보지 말 것)

- 훅은 `Write` / `Edit` 에만 걸린다. `Bash` 로 고친 `plugin.json` 은 못 막는다. `--all` 에서 잡힌다.
- `PreToolUse` 는 **버전 값만** 본다. CHANGELOG 정합성(`V-06`)은 막지 않는다 — 두 번의 편집이 필요하므로 첫 편집에서 막으면 아무것도 못 한다.
- Edit 의 `new_string` 은 부분 문자열이라 JSON 으로 못 읽는다. `"version": "..."` 패턴을 정규식으로 찾는다. 그 패턴이 없으면 조용히 넘어간다.
- **올림 등급(PATCH/MINOR/MAJOR)은 판정하지 않는다.** `version-update` 스킬의 몫이다.
- 태그가 가리키는 커밋의 `plugin.json` 은 보지 않는다. 현재 작업 트리의 값과만 비교한다.
- 원격 소스(`github` · `npm` · `archive`) 엔트리는 로컬 `plugin.json` 과 대조하지 않는다. 대조할 파일이 없다.
