# 근거 리뷰

규칙 원본: [`references/evidence-rules.md`](../../references/evidence-rules.md)
근거: [`references/evidence-methods.md`](../../references/evidence-methods.md)

작성한 문맥에서 다시 읽는 것은 검증이 아니다 (`E-01`). 이 스킬은 판정할 것을 **결론 없이** 정리해 `evidence-reviewer` 에게 넘기고, 받은 판정대로 처리한다.

## 1. 범위

| 상황 | 대상 |
|---|---|
| 완료 게이트(`E-30`)가 되돌렸다 | 메시지에 나온 파일 · 요청 기록 · 주장 후보 |
| 사용자가 파일 · 커밋 범위를 지정했다 | 그것 |
| 그 밖 | 이번 작업에서 바꾼 것 — `git status --short` · `git diff` |

문서(`.md` 등)는 `document-slop-review` 의 몫이다. 여기서는 코드 · 설정 · 스크립트와 그에 대한 주장을 본다.

## 2. 넘길 것을 만든다

검증자에게는 셋만 넘긴다 (`E-02`).

1. **요청 원문**
   - 게이트 메시지의 요청 기록 파일이 있으면 그 내용을 넘긴다.
   - 없으면 대화에서 사용자가 쓴 요청을 고치지 않고 옮긴다. 요약하거나 해석하지 않는다.
2. **바뀐 파일 목록** — 또는 커밋 범위.
3. **질문 목록**
   - 내가 한 주장을 모은다. 최종 답, 게이트 메시지의 주장 후보, 작업 중에 한 말이 대상이다. 원인 · 버그 · 고침 · 통과 · 필요 · 동작 설명 · 수치를 담은 주장을 고른다.
   - 주장마다 **결론이 들어가지 않은 열린 질문**으로 바꾼다 (`E-03`).

| 내 주장 | 넘길 질문 |
|---|---|
| 빈 배열에서 `parse` 가 죽는 버그를 고쳤다 | `parse([])` 는 수정 전 · 후 코드에서 각각 무엇을 하는가? |
| 원인은 캐시 키 충돌이다 | `cacheKey(a)` 와 `cacheKey(b)` 는 각각 무엇을 반환하는가? 같은 값이면 어떤 동작이 나오는가? |
| 테스트 전부 통과 | `npm test` 의 종료 코드와 실패 수는? 새 테스트를 수정 전 코드에 돌리면 어떻게 되는가? |
| `util.ts` 정리도 필요했다 | `util.ts` 의 변경을 되돌리면 무엇이 달라지는가? |

넘기지 않는 것: 내가 왜 그렇게 했는지, 무엇이 맞다고 보는지, 작업 요약, 커밋 메시지, 예/아니오 질문 ("X 맞지?"). "무시하라" 고 덧붙여도 판정이 끌린다.

## 3. 검증자를 부른다

`evidence-reviewer` 에이전트를 부른다. 프롬프트는 아래 형식만 쓴다.

```
요청 원문:
<그대로>

바뀐 파일:
- <경로>

질문:
1. <열린 질문>
```

에이전트를 쓸 수 없는 환경이면 검증하지 못한 것이다. 스스로 다시 읽고 통과시키지 않는다. 사용자에게 `판정 불가` 로 알린다.

## 4. 대조하고 처리한다

검증자의 질문 답을 내 주장과 맞춘다. 답이 주장과 다르면 그 주장은 `틀림` 이다. 새 실행 근거 없이 내 기억으로 뒤집지 않는다 (`E-11`).

| 판정 | 처리 |
|---|---|
| `틀림` (변경 · 주장) | 고친다. 주장이면 답에서 바로잡는다 |
| `불필요함` | 되돌린다. 사용자가 원했을 수 있는 변경이면 되돌리기 전에 묻는다 |
| `판정 불가` | 지우지 않는다. 답에 `미확인` 과 이유를 밝힌다 |
| `필요함` · `맞음` | 그대로 둔다 |

- 고쳤으면 고친 부분만 다시 검증자에게 넘긴다.
- 재검증은 2회까지다. 그래도 `틀림` · `판정 불가` 가 남으면 사용자에게 넘긴다.

## 5. 보고한다

```
근거 리뷰 — <범위>
- 변경: 필요 N · 불필요 N (되돌림 N) · 판정 불가 N
- 주장: 맞음 N · 틀림 N (바로잡음) · 미확인 N
- 바꾼 것: <위치> <판정> <무엇을 어떻게>
- 미확인: <주장> — <이유>
```

전부 `필요함` · `맞음` 이면 "결함 없음" 과 판정한 단위 · 질문 수만 쓴다.

## 지키지 않을 것

- 검증자가 문제를 못 찾았다고 근거 없는 주장이 확인된 것은 아니다. 답이 `판정 불가` 면 `미확인` 이다.
- 사용자가 확신해도 판정을 바꾸지 않는다. 바꾸려면 새 실행 근거를 낸다.
- 리뷰를 핑계로 요청 밖의 것을 고치지 않는다.
