# 도메인 문서 테스트

`scripts/domain-document-sync.sh` 의 회귀 테스트. 규칙이나 스크립트를 고치면 여기부터 돌린다.

## 실행

```bash
test/domain-document-sync.test.sh          # 전체
test/domain-document-sync.test.sh TC-C     # ID 접두사로 필터
```

종료 코드 0 이면 전체 통과다. 필요한 것: `git`, `jq`.

## 자동 TC (45건)

픽스처는 **모든 규칙을 지키는 저장소**다 — Java(`src/main/java/**/order/**`) · TypeScript(`web/src/features/order/`) · Python(`services/billing/**`) 세 언어, 블록 목록 · 인라인 목록 · `!` 제외, concept 이 있는 도메인 · `_meta.md` 만 있는 도메인 · `code:` 가 없는 도메인. TC 마다 한 곳만 깨뜨린다.

### A. validate (D-01 ~ D-08)

| ID | 케이스 |
|---|---|
| TC-A01 | 모든 규칙을 지킨 저장소는 통과한다 — 경고 없음 |
| TC-A02 | 문서 루트가 없으면 막는다 (D-01) |
| TC-A03 | `_index.md` 가 없으면 막는다 (D-01) |
| TC-A04 | `_meta.md` 없는 도메인 디렉터리를 막는다 (D-02) |
| TC-A05 | kebab-case 가 아닌 slug 를 막는다 (D-03) |
| TC-A06 | 카탈로그에 없는 도메인을 막는다 (D-04) |
| TC-A07 | 메타 파트 표에 없는 concept 을 막는다 (D-05) |
| TC-A08 | `./` 로 시작하거나 `#앵커` 가 붙은 링크도 등재로 본다 (D-05 과잉 차단 방지) |
| TC-A09 | 깨진 상대 링크를 막는다 (D-06) |
| TC-A10 | 코드 블록 · `{}` 자리표시자 · 외부 URL · 앵커 링크는 보지 않는다 (D-06 과잉 차단 방지) |
| TC-A11 | concept 이 300줄을 넘으면 경고만 한다 (D-07) |
| TC-A12 | `DOMAIN_DOCUMENT_MAX_LINES` 로 상한을 바꾼다 |
| TC-A13 | 걸리는 파일이 없는 `code:` 글롭을 경고한다 (D-08) |
| TC-A14 | `DOMAIN_DOCUMENT_ROOT` 로 문서 루트를 바꾼다 |

### B. code 글롭 (map)

| ID | 케이스 |
|---|---|
| TC-B01 | 블록 목록 · 인라인 목록 · 디렉터리 글롭 · `!` 제외를 읽는다 |
| TC-B02 | `code:` 가 없는 도메인은 게이트 대상이 아니라고 표시한다 |
| TC-B03 | `*` 는 `/` 를 넘지 않는다 |

### C. 동기 게이트 (S-01)

| ID | 케이스 |
|---|---|
| TC-C01 | 코드가 안 바뀐 요청(질문 · 조회)은 막지 않는다 |
| TC-C02 | Java 도메인 코드만 바뀌면 막는다 — 다른 도메인은 거론하지 않는다 |
| TC-C03 | TypeScript 새 파일(untracked)도 잡는다 |
| TC-C04 | Python 도메인(인라인 `code:` 목록)도 잡는다 |
| TC-C05 | 지운 파일도 변경으로 본다 |
| TC-C06 | 그 도메인 문서도 바뀌었으면 통과한다 |
| TC-C07 | 다른 도메인 문서만 바뀌면 막는다 |
| TC-C08 | `!` 로 뺀 테스트 파일만 바뀌면 막지 않는다 |
| TC-C09 | 어느 도메인에도 안 걸리는 코드는 막지 않는다 |
| TC-C10 | 요청 전부터 있던 변경은 이번 요청에서 안 바뀌었으면 막지 않는다 |
| TC-C11 | 요청 전부터 있던 변경을 이번 요청에서 또 바꾸면 막는다 |
| TC-C12 | 스냅샷이 없으면(설치 직후) 변경이 있는 도메인을 본다 |
| TC-C13 | 면제 `n/a <slug>` 는 그 도메인만 통과시킨다 |
| TC-C14 | 면제 `n/a` 는 모든 도메인을 통과시킨다 |
| TC-C15 | 면제는 다음 요청(snapshot)에서 지워진다 |
| TC-C16 | 차단 메시지에 면제 파일 경로가 나온다 |
| TC-C17 | 한 번 되돌린 뒤(`stop_hook_active`)에는 막지 않고 `systemMessage` 로 알린다 |
| TC-C18 | 문서 루트가 없는 저장소에서는 아무것도 하지 않는다 |
| TC-C19 | git 저장소가 아니면 아무것도 하지 않는다 |
| TC-C20 | 프로젝트가 저장소 하위 디렉터리여도 경로를 프로젝트 기준으로 본다 |

### D. 편집 훅 (pre-edit · post-edit)

| ID | 케이스 |
|---|---|
| TC-D01 | 문서 루트 밖 편집에는 아무것도 하지 않는다 |
| TC-D02 | 카탈로그 편집에 네 갈래 트리거를 주입한다 |
| TC-D03 | 기존 도메인 concept 편집에 메타 · 카탈로그 동기를 주입한다 |
| TC-D04 | 새 도메인 파일이면 `_meta` · `_index` 를 같이 만들라고 한다 (D-02 · D-04) |
| TC-D05 | 300줄을 넘긴 concept 을 알린다 (D-07) — 등재된 파일이면 D-05 는 없다 |
| TC-D06 | 메타에 없는 새 concept 을 알린다 (D-05) — 짧으면 D-07 은 없다 |
| TC-D07 | `_meta` · `_index` 편집 뒤에는 알리지 않는다 |
| TC-D08 | `jq` 가 없으면 훅은 조용히 통과한다 (fail-open) |
