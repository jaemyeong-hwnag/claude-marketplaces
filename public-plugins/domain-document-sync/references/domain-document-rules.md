# 도메인 문서 규칙 (단일 원본)

대상 저장소의 **도메인 지식 문서**를 어떻게 두고, 읽고, 코드와 맞추는가를 정한다. 스킬 · 커맨드 · 훅은 모두 이 문서를 참조한다.
기계 검증은 [`scripts/domain-document-sync.sh`](../scripts/domain-document-sync.sh), 문서 골격은 [`templates.md`](templates.md).

언어 · 프레임워크 · 디렉터리 구조를 가정하지 않는다. 어떤 코드가 어느 도메인인지는 각 도메인의 `_meta.md` 가 글롭으로 말한다.

## 1. 3계층

```
docs/domain/                      # 문서 루트 — DOMAIN_DOCUMENT_ROOT 로 바꾼다
  _index.md                       # 카탈로그 — 도메인당 1행
  {slug}/
    _meta.md                      # 도메인 메타 — 파트 표 · 관계 · code 글롭
    {concept}.md                  # 개념 본문 — 규칙 · 엔티티 · 흐름
```

| 계층 | 파일 | 담는 것 | 언제 읽나 |
|---|---|---|---|
| 카탈로그 | `_index.md` | 도메인명 · 한 줄 · 트리거 (말 · 식별자 · 경로 · 증상) · "겹칠 때" 표 | 도메인 지식이 필요할 때 항상 — 가볍다 |
| 도메인 메타 | `{slug}/_meta.md` | 한 줄 · 코드 위치 · 관계 · 파트 표(파일 · 언제 본다) · `code:` 글롭 | 카탈로그에서 걸린 도메인만 |
| 개념 본문 | `{slug}/{concept}.md` | 실제 규칙 · 엔티티 · 흐름 · 상태 · 예외 | 메타 파트 표에서 걸린 파일만 |

### 왜 3계층인가

- **발견 비용이 선형이고 작다** — 카탈로그는 도메인 수에 비례하는 몇 줄이라 도메인이 수백 개여도 먼저 읽을 수 있다
- **신선도가 다르다** — 분류 · 관계(메타)는 잘 안 바뀌고 규칙(개념)은 자주 바뀐다. 나누면 개념만 고쳐도 메타는 그대로다
- **두 단계로 좁힌다** — 카탈로그 → 메타 → 개념. 좁은 작업이 도메인 전체를 읽지 않는다. 나중에 검색 계층(임베딩)을 메타에만 얹기 좋다

## 2. 조항

| 조항 | 내용 | 판정 |
|---|---|---|
| `D-01` | 문서 루트와 `_index.md` 가 있다 | 차단 (`validate`) |
| `D-02` | 도메인 디렉터리마다 `_meta.md` 가 있다. 작은 도메인은 `_meta.md` 하나로 끝나도 된다 | 차단 (`validate`) · 알림 (훅) |
| `D-03` | slug 는 영문 kebab-case — 코드 · 경로에서 부르는 이름과 같게 | 차단 (`validate`) |
| `D-04` | 모든 도메인이 `_index.md` 에 `[{slug}/]({slug}/_meta.md)` 링크로 1행 있다 | 차단 (`validate`) |
| `D-05` | 모든 concept 이 자기 `_meta.md` 파트 표에 링크로 있다 | 차단 (`validate`) · 알림 (훅) |
| `D-06` | 문서 안의 상대 링크는 실제 파일을 가리킨다 (코드 블록 · `{}` 자리표시자 제외) | 차단 (`validate`) |
| `D-07` | concept 이 300줄(`DOMAIN_DOCUMENT_MAX_LINES`)을 넘으면 "언제 보는가" 기준으로 나눈다 | 경고 · 알림 (훅) |
| `D-08` | `code:` 글롭마다 걸리는 파일이 하나 이상 있다 — 없으면 코드가 옮겨진 것이다 | 경고 (`validate`) |
| `S-01` | 한 요청에서 도메인의 `code:` 파일이 바뀌었는데 `{루트}/{slug}/` 에 변경이 없으면 작업을 끝내지 못한다 | 차단 (Stop 훅) |

## 3. 코드 ↔ 도메인 매핑 (`code:`)

`_meta.md` 맨 위 프런트매터에 적는다. 경로는 **프로젝트 루트 기준**이다.

```yaml
---
code:
  - "src/main/java/**/order/**"         # Java · Kotlin
  - "apps/*/src/features/order/**"      # 모노레포 TypeScript
  - "services/order/"                   # 디렉터리 전체 (끝 /)
  - "db/migrations/*order*.sql"
  - "!**/*.test.*"                      # ! 로 뺀다
  - "!**/test/**"
---
```

| 글롭 | 뜻 |
|---|---|
| `**/` | 0개 이상 디렉터리 |
| `**` | 무엇이든 (`/` 포함) |
| `*` · `?` | `/` 를 넘지 않는 0개 이상 · 1개 |
| 글롭 문자 없음 | 그 파일, 또는 그 디렉터리 아래 전부 |
| `!` 로 시작 | 앞 글롭에 걸린 것에서 뺀다 |

- `code:` 가 없는 도메인은 `S-01` 대상이 아니다 — 정책 · 용어처럼 코드가 없는 도메인
- 한 파일이 두 도메인에 걸려도 된다. 공용 코드가 바뀌면 두 도메인 문서를 다 본다
- 좁게 쓴다. `src/**` 처럼 넓으면 모든 변경이 이 도메인 문서를 요구한다
- 확인: `domain-document-sync.sh map .` 이 도메인별로 걸리는 파일 수를 보여 준다

## 4. 동기 게이트 (`S-01`)

| 시점 | 무엇을 |
|---|---|
| `UserPromptSubmit` | 도메인마다 지금 바뀐 `code:` 파일의 내용 지문을 저장하고, 지난 요청의 면제를 지운다 |
| `Stop` | 지문이 달라진 도메인 = **이번 요청에서** 코드가 바뀐 도메인. 그중 `{루트}/{slug}/` 가 HEAD 와 같은 도메인이 있으면 `exit 2` |

- 판정 기준은 git 작업 트리다 (HEAD 대비 tracked 변경 + untracked). `Edit` · `Write` · `Bash` 어느 것으로 고쳤든 잡힌다. 커밋과는 무관하다
- 질문 · 조회만 한 요청은 지문이 그대로라 막지 않는다
- 한 번 되돌려진 뒤(`stop_hook_active`)에도 안 맞으면 끝내게 두고 사용자에게 `systemMessage` 로 알린다 — 무한 루프 방지
- **면제** — 도메인 지식이 그대로인 변경(내부 리팩터 · 오타 · 테스트 · 포맷)은 사용자에게 알린 뒤 세션 면제 파일에 `n/a {slug}` (전체면 `n/a`) 를 쓴다. 경로는 차단 메시지에 나온다. 면제는 그 요청에만 유효하다

## 5. 읽기 (read)

1. `_index.md` 에서 트리거로 후보 도메인을 좁힌다. 애매하면 "겹칠 때" 표를 보고, 그래도 애매하면 후보 2 ~ 3개
2. 후보의 `_meta.md` 파트 표에서 관련 concept 을 고른다
3. 고른 concept 만 읽는다. 검색도 두 단계 — `_meta.md` 먼저, 좁힌 뒤 concept
4. 문서와 코드가 다르면 **코드가 맞다**. 문서를 고칠 대상으로 기록한다

## 6. 쓰기 (write)

| 변경 | 고칠 곳 |
|---|---|
| 규칙 · 흐름 · 필드가 바뀜 | concept |
| 파트가 늘거나 나뉨, "언제 본다" · 관계 · `code:` 가 바뀜 | + `_meta.md` |
| 도메인 한 줄 · 트리거가 바뀜, 도메인 추가 · 삭제 | + `_index.md` |

- **안 바뀐 계층은 건드리지 않는다** — 신선도 분리
- 트리거는 네 갈래로 쓴다: **말**(화면 · 기획 용어) · **식별자**(테이블 · 클래스 · enum · 필드) · **경로**(엔드포인트 · 명령 · 토픽) · **증상**(버그로 들어올 때의 문구). 질문은 대개 이 중 하나로만 온다
- 키워드가 두 도메인에 걸리면 `_index.md` "겹칠 때" 표에 어느 쪽을 고르는지 1행
- 상호 참조는 상대 경로 — 같은 도메인 `{concept}.md`, 다른 도메인 `../{slug}/_meta.md`
- 사실만 쓴다. 코드에서 확인한 것만, 위치(파일 · 심볼)와 함께. 추측은 "확인 필요" 로 표시한다

## 7. 설정

| 환경 변수 | 기본 | 뜻 |
|---|---|---|
| `DOMAIN_DOCUMENT_ROOT` | `docs/domain` | 문서 루트 (프로젝트 기준) |
| `DOMAIN_DOCUMENT_MAX_LINES` | `300` | concept 줄 수 상한 (`D-07`) |

프로젝트 `.claude/settings.json` 의 `env` 에 둔다. 문서 루트가 없는 저장소에서는 훅이 아무것도 하지 않는다.
