# 도메인 문서 골격

규칙은 [`domain-document-rules.md`](domain-document-rules.md). `{…}` 를 채운다. 모르는 칸은 지우지 말고 "확인 필요" 로 둔다.

## `_index.md`

```markdown
# 도메인 카탈로그

도메인 지식이 필요하면 여기서 후보를 좁힌 뒤 `{slug}/_meta.md` → concept 순으로 연다. 도메인당 1행.

트리거는 네 갈래 — **말**(화면·기획 용어) · **식별자**(테이블·클래스·enum·필드) · **경로**(엔드포인트·명령·토픽) · **증상**(버그로 들어올 때의 문구).

| 도메인 | 한 줄 | 트리거 | 경로 |
|---|---|---|---|
| **{이름} ({slug})** | {무엇을 다루나 — 한 문장} | **말**: {…} · **식별자**: `{…}` · **경로**: `{…}` · **증상**: {…} | [{slug}/]({slug}/_meta.md) |

## 겹칠 때 무엇을 고르나

| 들어온 말 | 고르는 곳 |
|---|---|
| {두 도메인에 걸리는 키워드} | {조건}이면 [{slug-a}]({slug-a}/_meta.md), {조건}이면 [{slug-b}]({slug-b}/_meta.md) |
```

## `{slug}/_meta.md`

```markdown
---
code:
  - "{이 도메인 코드 글롭}"
  - "!{뺄 글롭 — 테스트 등}"
---

# {이름} ({slug}) — 도메인 메타

- **한 줄**: {무엇을 다루나}.
- **위치**: {핵심 모델 · 서비스 · API 가 있는 모듈 / 디렉터리}.
- **관계**: [{다른 도메인}](../{slug}/_meta.md) — {어떻게 연결되나}.

## 파트 (언제 어느 파일)

| 파트 | 파일 | 언제 본다 |
|---|---|---|
| {엔티티 · 모델} | [entities.md](entities.md) | {필드 · 관계 · 상태값을 알아야 할 때} |
| {흐름 · API} | [flows.md](flows.md) | {엔드포인트 · 처리 순서를 고칠 때} |

> 좁은 작업이면 위 표에서 해당 파트만 연다.
```

작은 도메인은 파트 표 대신 본문을 `_meta.md` 에 바로 쓴다. 300줄에 가까워지면 concept 으로 뺀다.

## `{slug}/{concept}.md`

```markdown
# {이름} — {파트}

{2 ~ 3줄 — 무엇을, 어느 흐름을 다루나}.

> 코드: `{파일 · 심볼}`. 관련: [{다른 파트}]({concept}.md), [{다른 도메인}](../{slug}/_meta.md).

## 1. {규칙 · 엔티티 · 흐름}

## 함정

| 증상 | 원인 | 위치 |
|---|---|---|
| {버그로 들어오는 문구} | {왜} | `{파일:심볼}` |
```

## concept 을 어떻게 나누나

"무엇에 대한 것인가" 가 아니라 **"언제 보는가"** 로 나눈다. 한 작업이 파트 하나만 열면 되게.

| 흔한 파트 | 담는 것 |
|---|---|
| `entities` | 모델 · 테이블 · 필드 · 상태값 · 관계 |
| `flows` | 유스케이스별 처리 순서 · 상태 전이 · 트랜잭션 경계 |
| `api` | 외부 계약 — 엔드포인트 · 이벤트 · 메시지 · 응답 필드 |
| `rules` | 계산식 · 검증 · 권한 · 정책 |
| `integration` | 다른 도메인 · 외부 시스템과의 연동 |
