# 문서 slop 리뷰

규칙 원본: [`references/document-slop-rules.md`](../../references/document-slop-rules.md)
근거: [`references/document-slop-methods.md`](../../references/document-slop-methods.md)

훅이 명백한 흔적(`DS-01` ~ `DS-04`)을 막고 문체 신호(`DS-05` ~ `DS-16`)를 알린다. 이 스킬은 **판단이 필요한 것**을 본다. 내용이 맞는지, 필요한지, 정리돼 있는지다 (`DS-20` ~ `DS-27`).

## 1. 범위

| 상황 | 대상 |
|---|---|
| 종료 게이트(`DS-30`)가 되돌렸다 | 메시지에 나온 문서 |
| 사용자가 파일 · 디렉터리를 지정했다 | 그 경로 |
| 그 밖 | 이번 작업에서 고친 문서 — `git diff --name-only` |

## 2. 기계 검사

```bash
"${CLAUDE_PLUGIN_ROOT}/scripts/document-slop-validate.sh" <문서...>
"${CLAUDE_PLUGIN_ROOT}/scripts/document-slop-validate.sh" --diff     # 기본 브랜치 대비 바뀐 줄
```

- 차단(❌)은 먼저 고친다.
- 경고(⚠️)는 후보다. 맥락을 읽고 `확정` · `오탐` 을 가른다. 오탐인데 계속 걸리면 그 줄에 `<!-- document-slop-ignore -->` 를 단다.

## 3. 사실 대조 — `DS-20`

**초안을 쓴 맥락 밖에서** 대조한다. 스스로 다시 읽고 고치는 방식은 효과가 없다 (근거 4절).

- `document-slop-reviewer` 에이전트에게 문서 경로만 넘긴다. 작성 의도나 설명은 넘기지 않는다.
- 에이전트가 없는 환경이면, 아래 순서를 이 대화에서 직접 하되 초안을 쓸 때의 기억이 아니라 파일 · 명령 결과만 근거로 삼는다.
  1. 사실 주장을 뽑는다. 경로 · 명령 · 옵션 · 설정 키 · API · 버전 · 수치 · 날짜 · 동작 설명 · 외부 출처 인용이 대상이다.
  2. 주장마다 검증 질문을 하나씩 만들고, 저장소 파일 · 명령 실행 · 링크로 답한다.
  3. 판정은 `확인함` (근거 경로) · `틀림` (바른 값) · `미확인` 중 하나다.
- `틀림` 은 고친다. `미확인` 은 지우지 말고 문장에 `미확인` 이라고 밝힌다 (`P4`).

## 4. 판단 — `DS-21` ~ `DS-27`

| 조항 | 묻는 것 |
|---|---|
| `DS-21` | 이 문장을 지우면 독자가 잃는 정보가 있는가. 없으면 지운다. 채움 절 · 상투적 서두와 결말 · 코드를 보면 아는 설명 · 자명한 지시가 대상이다 |
| `DS-22` | 문서 목적에 기여하는가 |
| `DS-23` | 제목 · 서론 · 앞 절을 되풀이하는가. 같은 주제의 다른 문서가 있는가 (`grep -ril` 로 찾는다) |
| `DS-24` | 유형이 하나인가 (tutorial · how-to · reference · explanation). 핵심이 앞에 있는가 |
| `DS-25` | 목록 · 표가 서로 떨어진 항목에만 쓰였는가. 이어지는 설명을 목록으로 쪼개지 않았는가 |
| `DS-26` | 독자가 다시 해석 · 수습해야 하는 곳이 있는가. 결정 없이 선택지만 나열했거나 지시가 모호한 곳 |
| `DS-27` | 같은 개념에 다른 단어를 섞었는가. 프로젝트 용어가 일반어로 바뀌었는가 |

지키지 않을 것:
- 출처 · `미확인` 표시 · 단서 · 반박 근거는 `DS-21` 로 지우지 않는다 (`P5`).
- 길이나 문체 인상만으로 지적하지 않는다. 대조할 수 있는 근거를 댄다 (`P7`).
- 사용자가 확신해도 사실 판정을 바꾸지 않는다.

## 5. 고치고 보고한다

결함만 고친다. 리뷰를 핑계로 문서를 새로 쓰지 않는다.

보고 형식:

```
문서 slop 리뷰 — <파일>
- 사실 대조: 확인함 N · 틀림 N (고침) · 미확인 N (표시함)
- 고친 것: <줄> <조항> <무엇을 어떻게>
- 남긴 것: <줄> <조항> <왜 두었나>
```

결함이 없으면 "결함 없음" 과 대조한 주장 수만 적는다.

## 문서를 쓸 때

이 스킬은 문서를 쓰기 전에 읽어도 된다. 훅이 걸 것을 미리 피한다.

- 첫 문장에 핵심을 쓴다. 문서가 무엇을 할지 예고하지 않는다.
- 끝에 요약 절을 두지 않는다.
- 주장에는 출처(경로 · 명령 · 링크)를 같은 줄에 단다. 확인하지 못했으면 `미확인` 이라고 쓴다.
- 날짜가 지나면 틀리는 말(`최근`, `최신`)에는 기준일을 단다.
- 경로 · 명령 · 옵션은 실제로 있는 것만 쓴다. 쓰기 전에 연다.
- 굵게 · 목록은 필요한 곳에만 쓴다. 이어지는 설명은 문장으로 쓴다.
