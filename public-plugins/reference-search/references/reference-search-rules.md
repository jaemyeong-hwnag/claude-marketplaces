# reference-search 규칙

이 문서가 규칙 원본이다. 스킬 · 에이전트 · 스크립트는 이 문서의 조항 번호로 말한다.
근거는 [`reference-search-methods.md`](./reference-search-methods.md), 절차는 [`search-orchestration.md`](./search-orchestration.md), 형식은 [`result-schema.md`](./result-schema.md).

## 1. 기계가 막는 것 — `reference-validate.sh`

| 조항 | 내용 | 처리 | 어디서 |
|---|---|---|---|
| `RS-01` | 새로 쓰는 DOI 가 등록돼 있지 않다 (DOI 핸들 조회 404) | 차단 | 훅 · `/reference-validate` |
| `RS-02` | 새로 쓰는 arXiv ID 가 없다 (arXiv abs 조회 404. arXiv 가 한도에 걸리면 arXiv DOI `10.48550/arXiv.<ID>` 로 다시 본다) | 차단 | 훅 · `/reference-validate` |
| `RS-03` | DOI 가 철회된 논문이다 (OpenAlex `is_retracted`) | 알림 | 훅 · `/reference-validate` |
| `RS-04` | 확인하지 못했다 — 시간 초과 · 429 · 상한(기본 20개) 초과 | 통과 + 알림 | 훅 · `/reference-validate` |
| `RS-05` | URL 이 404 · 410 이다 | 실패 | `/reference-validate --urls` |
| `RS-06` | URL 이 401 · 403 · 429 같은 접근 제한이다 | 경고 | `/reference-validate --urls` |

- 훅은 PreToolUse `Write|Edit|MultiEdit` 의 `.md` · `.markdown` 파일만 본다.
- "새로" 는 파일 · `old_string` 에 없던 식별자다. 기존 문서를 고칠 때마다 전부 다시 조회하지 않는다.
- URL 은 훅에서 보지 않는다. 유료 장벽 · 봇 차단으로 오탐이 많고 느리다.
- 인라인 코드 · 코드 펜스 안의 식별자는 예시로 보고 보지 않는다.
- 출판사 URL 에 든 DOI 는 꼬리(`.pdf` · `/abstract` · bioRxiv 버전 `v1` · 쿼리)를 떼고 조회한다. 한국어 조사처럼 DOI 바로 뒤에 붙은 글자는 DOI 에 넣지 않는다.
- 있다고 확인한 식별자는 `${CLAUDE_PLUGIN_DATA}` 에 캐시한다 (철회 여부 포함). 없다고 나온 것은 캐시하지 않는다.
- 네트워크가 없으면 막지 않는다 (`RS-04`). 오프라인 작업을 멈추지 않는다.
- `REFERENCE_VALIDATE=off` 로 끈다.

## 2. AI 가 지키는 것 — 스킬 · 에이전트

| 조항 | 내용 |
|---|---|
| `RS-10` | 결과 항목은 도구 결과(스크립트 출력 · 검색 결과 · 열어 본 페이지)에서 온 것만 쓴다. 기억으로 제목 · 저자 · 식별자를 채우지 않는다 |
| `RS-11` | 항목마다 식별자 하나 이상(DOI → arXiv ID → URL), 상태 값, 찾은 경로를 단다 (`result-schema.md`) |
| `RS-12` | 결과 맨 위에 기준일 · 검색 범위(기간 · 언어 · 깊이 · 띄운 에이전트) · 건수(찾음 → 병합 뒤 → 검증 통과) · 실패하거나 빠진 출처를 적는다 |
| `RS-13` | 요지는 초록 · 본문을 열어 본 것만 쓴다. 제목만 봤으면 `제목만 확인`, 확인 못 한 주장은 `미확인` |
| `RS-14` | 같은 논문의 프리프린트와 출판본은 한 항목으로 합치고 출판본을 앞에 둔다 |
| `RS-15` | 프리프린트 · 학회 투고 · 기업 블로그 · 커뮤니티는 심사 완료 논문과 같은 무게로 쓰지 않는다. 상태를 결론 문장에도 밝힌다 |
| `RS-16` | 철회 · 우려 표명 · 폐기된 표준은 빼지 않고 표시한다. 결론의 근거로는 쓰지 않는다 |
| `RS-17` | 기업 자료는 회사 · 날짜를 밝히고, 3년이 넘은 사례는 지금도 유효한지 `미확인` 으로 표시한다 |
| `RS-18` | 결론을 떠받치는 항목은 `reference-reviewer` 에게 존재 `확인` · 지지 `지지` 를 받은 것만 쓴다. 존재 `없음` 은 빼고, `불일치` 는 고치고, 지지 `부분` · `아님` 은 요지를 좁히거나 뺀다 |
| `RS-19` | 깊이 · 에이전트 수는 요청 복잡도로 정하고, 사용자가 정한 값(깊이 · 개수 · 출처 지정 · 제외)이 있으면 그것을 따른다 (`search-orchestration.md` 2절) |
| `RS-20` | 하위 에이전트에게는 주제 · 검색어 후보 · 기간 · 언어 · 결과 개수 · 도구 호출 예산 · 다른 에이전트와 겹치지 않는 범위 · 멈춤 기준을 넘긴다 |

## 3. 판단에 맡기는 것

어느 출처가 이 질문에 맞는지, 검색어를 어떻게 넓힐지, 어떤 결과가 관련 있는지, 원문이 요지를 떠받치는지는 기계로 정하지 않는다. 위 조항은 그 판단이 기록 · 검증되게 만드는 틀이다.
