# Go 네이밍 테스트

`scripts/validate-go-naming.sh` 의 회귀 테스트. 규칙이나 스크립트를 고치면 여기부터 돌린다.

## 실행

```bash
test/validate-go-naming.test.sh          # 전체
test/validate-go-naming.test.sh TC-G3    # ID 접두사로 필터
```

종료 코드 0 이면 전체 통과다.

## 자동 TC (43건)

픽스처는 **규칙을 지키는 파일**(`order_service.go`)이고, TC 마다 한 곳만 깨뜨린다. 과잉 차단(막으면 안 되는 것)을 막는 TC 를 조항마다 둔다.

### A. CLI 조항 (GO-01 ~ GO-06)

| ID | 케이스 |
|---|---|
| TC-G01 | 이 저장소 전체가 통과한다 |
| TC-G02 | 규칙을 지킨 파일은 조용히 통과한다 (지역 변수 · 매개변수의 밑줄은 보지 않는다) |
| TC-G03 | 패키지에 밑줄이 있으면 막고 한 단어를 제안한다 (GO-01) |
| TC-G04 | 패키지에 대문자가 있으면 막는다 (GO-01) |
| TC-G05 | 외부 테스트 패키지의 _test 접미사 · main 은 허용한다 (GO-01 과잉 차단 방지) |
| TC-G06 | 함수 이름의 밑줄을 막고 공개 여부를 유지한 MixedCaps 를 제안한다 (GO-02) |
| TC-G07 | 메서드 · 타입 · 구조체 필드(중첩 · 여러 이름)의 밑줄을 막는다 (GO-02) |
| TC-G08 | 최상위 var · const 와 괄호 블록 안을 본다 — UPPER_SNAKE 는 MixedCaps 로 제안한다 (GO-02) |
| TC-G09 | 빈 식별자 · 임베딩 · import 별칭 · 여러 줄 식 · 태그는 이름으로 보지 않는다 (GO-02 과잉 차단 방지) |
| TC-G10 | _test.go 의 Test · Benchmark · Example · Fuzz 함수 밑줄은 허용한다 (GO-02 과잉 차단 방지) |
| TC-G11 | _test.go 가 아니면 Test 함수의 밑줄도 막는다 (GO-02) |
| TC-G12 | 이니셜리즘이 Title 케이스면 경고한다 (GO-03) |
| TC-G13 | 뒤에 소문자가 오는 단어 · 소문자 이니셜리즘은 경고하지 않는다 (GO-03 과잉 경고 방지) |
| TC-G14 | 매개변수 없는 GetX() 메서드를 경고한다 (GO-04) |
| TC-G15 | 매개변수가 있는 Get · 함수 GetX() 는 경고하지 않는다 (GO-04 과잉 경고 방지) |
| TC-G16 | 파일 이름의 대문자 · 하이픈을 경고한다 (GO-05) |
| TC-G17 | 소문자 · 숫자 · 밑줄 파일 이름은 경고하지 않는다 (GO-05 과잉 경고 방지) |
| TC-G18 | 리시버 this · self 를 경고하고 타입 약자를 제안한다 (GO-06) |
| TC-G19 | 짧은 리시버 · 이름 없는 리시버는 경고하지 않는다 (GO-06 과잉 경고 방지) |
| TC-G20 | 주석 · 문자열 · 룬 · 여러 줄 raw string 안의 단어는 코드로 읽지 않는다 |
| TC-G21 | 제네릭 함수 · 타입 이름도 본다 (GO-02) |
| TC-G22 | 함수 안의 type 선언은 보고, 지역 var 는 보지 않는다 |
| TC-G23 | 생성 파일(// Code generated ... DO NOT EDIT.)은 보지 않는다 |
| TC-G24 | 생성 표시가 package 뒤에 있으면 생성 파일로 보지 않는다 |
| TC-G25 | 디렉터리를 주면 하위 *.go 를 보고 vendor/ · testdata/ 는 건너뛴다 |
| TC-G26 | 루트가 .claude/worktrees 안이어도 검사한다 (제외는 루트 기준) |
| TC-G27 | --all 은 루트의 .claude/worktrees 를 건너뛴다 |
